# 设置与使用帮助

首次安装见 [README](../README.md)。发布包已带默认配置，只有需要调整时才编辑这些文件。

## 修改监听地址

用文本编辑器打开 DLL 旁的 `bilimani_iidx.json`，找到：

```json
"listen": "127.0.0.1:32133"
```

例如把端口改成 `32135`，保存后重启游戏，并把 OBS 地址里的 `32133` 同样改为 `32135`。

OBS 在另一台电脑时，把这里的 `127.0.0.1` 改为游戏电脑的局域网 IP，OBS 地址使用相同 IP。这种用法只适合可信局域网，不要把端口开放到公网。

## 调整点歌规则

打开所用页面的配置：

| 页面 | 文件 |
|---|---|
| Mecha | `bilimani_web/iidx/mecha/config.json` |
| Card | `bilimani_web/iidx/card/config.json` |

`requests.prefix` 是点歌命令，默认“点歌”；`requests.cooldownSeconds` 是同一观众两次点歌的间隔秒数，默认 `0` 表示不限制。保存后，在 OBS 中刷新该浏览器来源。

点歌队列长度和等待开曲的时限在 `bilimani_iidx.json` 中修改，保存后重启游戏。全部字段见[配置说明](behavior.md#配置)。

## 左下角歌曲与玩家信息

Mecha 页面在歌曲信息和 DJ NAME、SP/DP 段位、DJ POINT、本周游玩次数及按键数之间滚动切换。默认每 10 秒换一次；在该页面的 `config.json` 中修改 `display.infoRotationSeconds`，保存并刷新 OBS 浏览器来源即可。可填 1–3600 的整数秒数。

没有登录玩家时只显示歌曲；没有选择歌曲时直接显示玩家。统计采用游戏的“本周”口径，按键数不含转盘；暂无数据时显示 `—`。玩家资料采用数值在上、说明在下的两行网格。

`display.vfdEffects` 默认为 `true`，启用滚动切换、候选屏的机械臂收放，以及歌曲/玩家资料处轻微的随机抖动和短促的局部高频闪动；BPM 保持稳定。动效由页面配置控制，不随 Windows 的动画设置关闭；需要静态展示时改为 `false`，保存并刷新浏览器来源。信息仍按设定间隔切换，候选屏直接显示或隐藏。

Mecha 有多个候选歌曲时，会从画面外伸出机械臂并降下荧光屏，弹幕和队列区域保持原有布局。1P 和 DP 从右侧伸出，2P 从左侧伸出；选完或超时后，先收起屏幕，再逐节收回机械臂。候选仍通过弹幕编号选择，翻页和待选观众轮换直接在屏幕内更新。

首次进入选曲前，Mecha 显示带柔焦、噪点的半透明蓝黑渐变遮罩，每 5 秒在“全加号＋左上等待提示”和“全叉号＋右下等待提示”之间切换。进入选曲后，提示在当前位置变为绿色“登录成功”，短暂闪烁后渐隐退出。底栏铺满蜂巢边框，随机六边形从左向右填实，再淡出循环，不代表实际进度；登录等待时蜂巢位于遮罩下面。选曲过程中暂时没有曲目信息时，也使用这套蜂巢动画，但不会重新遮住画面。`display.vfdEffects: false` 可将蜂巢设为静态，关闭成功提示的闪烁、渐隐，保留等待画面每 5 秒的切换。

## 添加歌曲别名

打开 DLL 旁的 `bilimani_iidx_aliases.csv`，保留第一行 `alias,target`，在下面每行填写一个别名和对应的完整曲名，用英文逗号分隔。例如：

```csv
alias,target
红武士,SAMURAI-Scramble
```

保存为 UTF-8 后，在游戏内菜单选择“重新加载别名 CSV”。如果填写有误，菜单会显示出错的行，之前已加载的别名继续有效。这里的曲名必须存在于当前游戏中。

## 点歌操作

- 发送 `点歌 曲名 SPA` 可以指定谱面。SP 和 DP 支持 B / N / H / A / L 难度。
- 候选歌曲每页显示 5 首，发送 `n` 看下一页，`p` 看上一页，再回复歌曲编号。默认需要在 60 秒内确认。
- 游戏内菜单可以删除队列中的歌曲、优先选某一首、跳过当前点歌以及重新加载别名。菜单打开期间暂停自动选曲。
- 刷新网页保留点歌队列；退出游戏清空队列。

## 常见问题

**网页打不开或显示找不到页面**

先确认游戏已经启动，启动参数中已加载 `bilimani_iidx.dll`，并且 `bilimani_web` 文件夹放在 DLL 旁边。核对 OBS 地址与 README 中一致；修改过监听地址时，OBS 也要同步修改。

**提示读取配置失败**

检查页面目录里的 `config.json` 是否存在。如果缺失，从发布包中补回；如果刚编辑过，检查是否漏了逗号或双引号。

**游戏内菜单打不开**

确认使用单人 SP，在普通选曲界面双击另一侧 Start，并使用 [spice2x 26-09-12 或更新版本](https://github.com/spice2x/spice2x.github.io/releases/tag/26-09-12)。

**需要进一步排查**

查看网页上的错误提示，以及 DLL 旁的 `bilimani_iidx.log`。向开发者反馈时，提供游戏版本、spice2x 版本、错误提示和复现步骤。

## DDR WORLD（实验支持）

本地预览：运行 `scripts\preview-ddr.bat`，然后打开 `http://127.0.0.1:32134/ddr/street/`。预览使用 Rust 模拟器的曲目信息及模拟弹幕，无需启动游戏或连接 Bilibili；保留终端窗口即可持续预览，输入 `quit` 停止。终端支持 `select`、`play`、`sp`、`dp`、`next`、`enqueue`。修改页面后运行 `node web/apps/ddr/build.mjs --preview` 并刷新浏览器。预览文件位于独立的 `dist/ddr-preview`，不会改写正式页面配置。

使用 MDX-003-2026022400 的 64 位 gamemdx.dll，加载 `bilimani_ddr.dll`。默认配置为 `bilimani_ddr.json`、`bilimani_ddr_aliases.csv`，静态页面在 `bilimani_web/ddr/street/`。只加载当前游戏对应的 DLL，默认监听 127.0.0.1:32133。

顶部展示主播名称和直播标题。名称和房间 ID 取自 blivechat 连接；页面通过 `platform.roomInfoUrl`（默认 `./_proxy/bilibili`，对应 `proxy.bilibili: https://api.live.bilibili.com`）查询 Bilibili 房间标题。每次加载页面只查询一次，不定时更新，也不因弹幕重连自动重查；手动刷新 OBS 浏览器源后重新查询。标题请求不携带身份码，失败不影响弹幕和点歌，断开后取消查询。`display.streamTitle` 留空时使用自动标题，也可以填写固定标题；可选的 `display.streamerName` 用于覆盖展示名。两项均仅影响当前页面，不用于连接或身份映射。预览中显示的是模拟名称和标题。底部只展示当前活动玩家实际选中的难度和等级；预览终端可输入 `chart ESP`、`chart CDP` 等切换。

OBS 地址为 `http://127.0.0.1:32133/ddr/street/?authCode=你的身份码`，浏览器来源尺寸为 1920×1080。DDR 游戏画面保持原生 1280×720，放在浏览器来源下方，位置为 x=48、y=174，不拉伸。Dance Dance Revolution 涂鸦位于左下角，弹幕和点歌位于右上角；主色为 #00d88d。页面读取相邻的 config.json，字体和涂鸦图片随静态资源打包。

摄像头在 OBS 中添加为「视频采集设备」，输入分辨率设为 1280×720，等比缩放到 **544×306**，位置设为 **x=1344、y=734**，旋转保持 0°，放在浏览器来源下方。右下角是透明摄像头窗口，倾斜喷漆边框会遮盖少量画面边缘，并向左覆盖游戏边缘；人物尽量居中。页面本身不打开摄像头设备。

点歌示例：`点歌 曲名 ESP`、`点歌 曲名 EDP`、`点歌 曲名 bSP`。bSP 是 BEGINNER，BSP 是 BASIC。模糊搜索、候选确认和 CSV 别名规则与 IIDX 相同。

在普通歌曲列表按 F8 开关队列菜单，方向键导航、Enter 确认、Esc 返回。`controls.enabled` 控制键盘快捷键。菜单只提供删除、优先选择和重新加载别名。目标歌曲必须在当前文件夹及筛选结果中；跳歌不会切换 SP/DP、解锁谱面或启动演奏。不可用的请求会报告错误。

当前提供曲名、艺人、谱面等级和玩家参与席位。玩家姓名、成绩和段位尚未验证，不展示。DDR 原生支持尚未实机验证。
