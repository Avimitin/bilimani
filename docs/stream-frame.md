# MECHA 直播框架

1920 × 1080 的机甲直播框架。页面背景透明，由 OBS 叠加在游戏来源上；游戏采集区域为严格 16:9 的 1504 × 846，左下角由放大的唱盘及装甲局部覆盖。顶部边框厚 24px，保留交错装甲板、散热槽、接缝、螺钉和灯条；右端为向下突出的梯形提示模块。直径 240px 的唱盘嵌入左侧立柱与底梁，周围使用错层、不规则连接板。底梁贴合信息窗外壳并延伸至画布底边。全部机身、玻璃和灯光均由 SVG 绘制。

底部显示游戏实际选曲／演奏的曲名、曲风、作者、BPM 范围、随机后的键位、时间轴密度及六项雷达；右侧从上到下依次显示队列、弹幕和点歌事件。底部信息窗从 y=890 开始，高 178px，雷达图为 116px；右侧是一体式互动显示窗。显示窗保留少量切角和接头凹口，采用黑色玻璃、细青绿边线、荧光文字；BPM 和待选倒计时使用带暗段底纹的七段数码管。全部由本地 CSS / SVG 绘制，无外部字体、图片或网络依赖。

## 安装独立静态包

1. 解压 `bilimani-green-room.zip`，将包内的 **`bilimani_web/mecha` 子目录**复制到 DLL 旁的 `bilimani_web` 中。实际选曲信息需要支持 `/api/now-playing` 的新版 DLL；旧 DLL 下页面继续显示当前点歌。升级歌曲信息功能时同时更新 DLL 和 Mecha 静态文件。
2. 在游戏控制台「OBS 显示」中，将「网页静态目录」设为 **`bilimani_web/mecha`**，点击应用并保存。
3. 在 OBS 添加浏览器来源，地址填 `http://127.0.0.1:32133/queue`，宽 **1920**、高 **1080**。游戏和插件须先启动；自定义端口时替换 `32133`。
4. 浏览器来源位置设为 **(0, 0)**，放在游戏采集来源的上方。移除以前为卡片添加的自定义 CSS；OBS 默认透明背景 CSS 可以保留。
5. 在 OBS 右键游戏采集来源，选择「变换 → 编辑变换」：位置设为 **X=40、Y=24**，位置对齐选左上角，大小设为 **1504 × 846**（严格 **16:9**）。将上下左右裁剪值全部设为 **0**，移除已有裁剪滤镜；若使用边界框，选择「缩放到内部边界」并设为 1504 × 846，避免使用会裁切画面的填满模式。1920 × 1080 游戏画面按 **78⅓%** 等比缩放后放入开口。
6. 刷新浏览器来源。采集区域范围为 **X=40–1544、Y=24–870**，左下角唱盘装饰有意覆盖部分画面，其他区域透明。旧版 Y=48 的来源需上移 24px，大小保持不变。非 16:9 的游戏来源请保持原始比例并留边，不要拉伸或裁剪。

切回卡片版时，将「网页静态目录」设为 **`bilimani_web/card`**。浏览器来源改回 **480 × 800** 并刷新。两种样式的 OBS URL 都是 `/queue`，不需要覆盖任何样式文件。

## 从源码或完整发布包使用

每种样式拥有独立的入口、CSS 和 JavaScript，没有对其他样式目录的资源依赖：

```text
web/
  card/       # 原始卡片样式（index.html、overlay.css、overlay.js）
  mecha/      # 机甲框架（index.html、overlay.css、frame.css、overlay.js）
```

完整 Windows 发布包的 `bilimani_web` 仅包含 `card` 和 `mecha` 两个样式目录，默认使用 `bilimani_web/card`。旧配置若仍指向根目录，请改为具体样式子目录。独立机甲 ZIP 只包含 `mecha` 子目录，可添加到已有安装。

选择样式目录后统一访问 `http://127.0.0.1:32133/queue`，由服务提供所选目录的 `index.html`。页面通过 `/api/state` 获取实时数据。

源码打包：`python scripts/package-frame.py`，生成 `dist/bilimani-green-room.zip`。

## 显示行为

- 歌曲信息使用锐角不规则荧光边框，上侧比下侧更亮，长曲名最多显示两行。底部难度牌和音符数已移除，BPM 保留在键位上方。七位键号使用 3px 微圆角矩形底板：青绿色蜂巢荧光带局部明暗变化，深色粗体数字呈现镂空效果。左上方小字显示 `RANDOM OFF`、`RANDOM`、`R-RANDOM`、`S-RANDOM`、`MIRROR` 或组合选项，底板下沿与密度图柱状区域下沿对齐；DP 的两组键位左右并排。
- 键号表示实际左至右七键对应的原谱键位，未开随机／镜像时显示 `1234567`，随机后按实际排列显示，例如 `3452167`。RANDOM／R-RANDOM 选曲时显示选项名和破折号，演奏开始后取得排列；重试会更新。S-RANDOM 逐音符变化，没有固定七键排列，也显示选项名和破折号。缺失／异常数据不会沿用旧排列。DP 显示两侧键位；旧 DLL 显示「等待键位数据」，需同步更新 DLL。
- 每个参与侧显示自己的 note 密度图：宽 380px，以老式 VFD 的 12 段灯条显示每 5 秒平均密度，超过 3 分钟的歌曲改为每 10 秒。青绿色低段、暗橙色高段，底部亮青绿表示包含在总量中的转盘；保留暗格底纹与两侧刻度。峰值标注仍使用原生 1 秒统计，结尾不足一窗按实际时长求均值，空白结尾保留。长押按原生口径在起点计 2 个 note；未取得数据时显示「暂无密度数据」。需要同时更新 DLL 与 Mecha 静态文件。
- 右上提示模块改为向下突出的梯形装甲，带错层侧板和不对称底部压边；提示文字为 20px，主播名字为 22px，左侧使用 bilibili 小电视 SVG，两行内容均居中。互动栏从 y=152 开始，高度 760px，底部事件区保持原位；弹幕正文为 20px、昵称 18px，仍按可用空间保留最近消息。
- 顶部横梁右端的显示模块常驻 `点歌 <曲名> [难度]` 格式提示，旁边显示当前已连接直播间的 UP 主名字，底部和队列区不再重复提示。长名字以省略号收尾，悬停可查看全名；断线显示「未连接」，名字尚未获取时留空。主播名字来自新版 DLL 的 `/api/state.room.name`，使用此功能需同时更新 DLL 与 Mecha 静态文件。待选时仍在候选列表中提示发送编号及 `n` / `p` 翻页。
- 歌曲信息来自 `/api/state.now_playing`，也可独立请求 `/api/now-playing`。手动选歌、切换难度及进入演奏都会更新，未收到点歌也可使用。每个参与侧显示其键位，雷达标明对应侧；缺失的 BPM／雷达显示破折号。选中目录、离开场景或演奏结束时清空旧歌。本版提供谱面 BPM 范围，未采集演奏进度和瞬时 BPM。字段说明见 [开发指南](development.md#当前选曲游玩歌曲-api)。
- 右侧最多显示 4 首等待歌曲；等待歌曲超出时显示剩余数量。队列为空且无人待选时隐藏队列，实时弹幕占满释放的空间，可见条数按实际行高和可用高度计算。弹幕间隔为 4px，单行按内容收紧，最多两行；每条下方有极淡的 1px 灰色分隔线。最近事件固定在右栏底部，使用小字号和较暗文字，始终只显示最近 3 条。弹幕与事件标题的数字表示「显示条数 / 当前服务端保留的该类条数」。仍使用服务端的共同历史上限（默认 10，可在控制台调整）。
- 搜索到多首歌曲时，候选列表临时替换右侧队列，每页最多 5 首，单列逐行展示，支持最多 20 首候选。由点歌本人发送弹幕 `n` 翻到下一页、`p` 翻到上一页（不区分大小写）；首页／末页继续向外翻时停留原页。编号始终对应完整列表，例如第二页发送 `6` 选择第六首，翻页不延长选择倒计时。页码保存在 DLL，每位观众独立，刷新网页后保留；多位观众每 6 秒轮换，收到翻页时优先展示刚翻页的观众。此功能需要同步更新 DLL，旧 DLL 不处理 `n` / `p`。
- 待选期间，青绿色荧光扫描带沿背景隔行纹理从上到下移动，每 2.6 秒一轮，文字保持稳定；扫描效果与玻璃共用同一轮廓，仅在候选区玻璃内部绘制，包含切角和接头凹口。选择结束后恢复普通玻璃。浏览器启用减少动态效果时仍保留此输入提示，但放慢到每 8 秒一轮，避免 OBS 继承系统设置后完全没有选歌动画。底部游戏歌曲信息保持可见。
- 断线后保留弹幕和事件，清除过时的当前点歌及队列，并显示等待连接提示；连接恢复后自动刷新。
- 框架尺寸固定为 1920 × 1080。较小浏览器窗口等比缩放，OBS 请按原始尺寸设置。
- `frame.css` 可调整 `--accent`、`--text`、`--muted` 等颜色和底部 `--title-size`；修改文件后刷新浏览器来源即可。

## 验证

交互开发可先运行 `py scripts/preview-overlay.py --style mecha`，打开
`http://127.0.0.1:32134/queue`。模拟歌曲、弹幕、队列和候选每 42 秒循环重播，修改页面后
刷新即可查看效果；无需 Rust、游戏或直播账号。时间表及速度设置见
[循环预览指南](development.md#循环时间轴预览前端开发)。

运行 `cargo run --example overlay_preview -- web/mecha` 启动机甲样式预览服务，再运行：

```sh
python -m pip install playwright pillow
python -m playwright install chromium
python scripts/check-frame.py
```

验证原始卡片样式时，先停止机甲预览服务，运行 `cargo run --example overlay_preview -- web/card`，再运行 `python scripts/check-overlay.py`。

也可通过 `--browser` 指定本机 Chromium 路径。框架检查使用本地模拟数据，覆盖机身与面板的连接、16:9 采集区域及唱盘装饰外的逐像素透明度、三种缩放比例下的开口尺寸、扫描动画的玻璃边界、布局边界、密度图、候选列表、长文字及离线恢复；截图输出到 `analysis/stream-frame/`。
